# 《R语言与数据可视化》第2讲教学设计

## 数据如何改变战争？——基于“克里米亚战争中士兵主要死亡原因研究”的 ggplot2 绘图基础微项目

**课程名称：** R语言与数据可视化  
**教学内容：** 第2讲 ggplot2绘图基础  
**教学对象：** 数据科学与大数据技术专业本科生，已学习R语言基本对象和数据框，尚未系统学习ggplot2  
**建议课时：** 90分钟（2学时，每学时45分钟）  
**项目类型：** 课堂微项目、历史真实数据项目、证据驱动决策项目  
**项目成果：** 1份可复现R脚本、2幅证据图、1段“结论—证据—建议”说明

## 一、课时选择结论

### 1. 建议采用90分钟

如果本讲的目标是让学生经历“提出问题—认识数据—选择图形—构建图形—解释证据—形成决策—评价图形”的完整项目闭环，建议安排90分钟。

90分钟能够完成：

1. 理解真实历史问题和项目任务；
2. 识别数据变量、比较死亡人数与死亡率；
3. 根据分析目的完成视觉映射设计；
4. 从普通柱形图逐步构建南丁格尔玫瑰图；
5. 比较不同图形的表达效果与局限；
6. 进行作品互评、代码解释和决策表达。

### 2. 45分钟可以实施，但只能定位为“项目核心课”

45分钟适合比赛实录或单课时教学，但必须把以下内容前置或后延：

- 课前完成项目背景阅读、软件与程序包检查、数据预览；
- 教师提供已经整理好的长数据，不在课内讲数据清洗与变形；
- 课堂只完成“分析目的—视觉映射—基础图形—极坐标变换—核心结论”；
- 图形美化、完整项目报告、互评修改放到课后。

因此，45分钟能够形成一个完整的“微循环”，但不足以支撑真正充分的项目探究。常规教学推荐90分钟；若用于教学竞赛或课堂实录，可采用“课前项目准备+45分钟核心探究+课后迁移完善”的设计。

## 二、项目化教学设计理念

本讲以真实历史问题为载体，以可交付成果为牵引，以学生探究和迭代改进为主要学习方式，突出以下项目化特征：

1. **真实问题驱动。** 学生不是为了练习函数而画图，而是作为“军队卫生改革数据顾问”，回答士兵主要死因及卫生改革是否有效。
2. **成果任务牵引。** 最终成果不是一幅“好看的图”，而是由图形、代码、证据结论和行动建议组成的小型数据报告。
3. **分析目的先行。** 先明确“比较什么、说明什么、支持什么决策”，再选择数据、图形和代码。
4. **知识在任务中建构。** `ggplot()`、`aes()`、`geom_*()`、`facet_*()`、`coord_*()`和`theme_*()`在解决任务的过程中逐层引入。
5. **多轮成果迭代。** 从数据表到普通柱形图，再到玫瑰图，最后比较两种表达方式并提出改进意见。
6. **过程性评价。** 评价数据理解、映射设计、代码解释、图表解读、人机协同和伦理表达，而不只评价代码能否运行。

## 三、项目背景

克里米亚战争期间，公众通常把士兵死亡归因于战斗和伤口。南丁格尔对军队医院和营地数据进行整理后发现，士兵死亡的主要原因并不是战伤，而是与卫生条件相关的可预防疾病。她使用极坐标面积图展示不同时期、不同死因的死亡率，用直观证据推动军队卫生改革。

课堂不把南丁格尔玫瑰图仅作为“经典名图”展示，而把它还原为一个真实的数据问题：

> 如果你是当时的军队卫生改革数据顾问，如何用数据和图形向不熟悉统计的决策者证明士兵的主要死亡原因，并提出有证据支持的改进建议？

该情境天然连接了数据分析、图形语法、公共决策与社会责任，能够体现“数据不仅用于描述世界，也能够推动现实改变”。

## 五、学情分析

### 已有基础

- 认识向量、数据框、变量及基本数据类型；
- 能够运行R脚本、查看数据和调用函数；
- 对柱形图、折线图等常见图形已有直观认识。

### 可能困难

1. 容易从“我要画玫瑰图”出发，而不是从分析目的出发；
2. 容易把变量名直接填入代码，却说不清变量为什么映射到位置、长度或颜色；
3. 容易混淆死亡人数与死亡率，忽视军队规模变化；
4. 容易把图形美观等同于图形有效，忽视极坐标面积带来的感知偏差；
5. 容易依赖AI直接生成完整代码，出现“图能画出，但代码不会解释”的情况。

### 教学应对

- 提供已整理好的长数据，把课堂认知负荷集中在图形语法与可视化决策；
- 使用“问题—变量—视觉通道—图层”映射表，帮助学生形成底层逻辑；
- 采用“先预测、后运行、再解释”的代码学习规则；
- 设置基础、标准、挑战三类任务，使不同基础学生都有可完成、可进阶的成果；
- 将AI限定为调试与评审工具，并保留对话记录和采纳理由。

## 六、教学目标

### 1. 知识目标

1. 理解ggplot2“数据+映射+几何对象+标度+坐标+分面+主题”的图形语法；
2. 掌握`ggplot()`、`aes()`、`geom_col()`、`facet_wrap()`、`coord_polar()`和`labs()`的基本作用；
3. 区分变量映射与属性设定，理解普通柱形图转换为极坐标图的基本原理。

### 2. 能力目标

1. 能够从真实问题中提取分析目的，并确定需要比较的变量；
2. 能够建立“变量—视觉通道—图层”的映射关系，独立完成基础证据图；
3. 能够将普通柱形图转换为极坐标面积图，并对图形进行基本标注；
4. 能够以“结论—证据—局限—建议”的结构解读图表。

### 3. 素质与价值目标

1. 形成尊重事实、重视证据和审慎表达的科学态度；
2. 理解数据可视化对公共健康和社会决策的价值；
3. 建立“不夸大、不隐瞒、不误导”的数据伦理意识；
4. 在AI辅助环境中保持对数据、代码和结论的主体判断与责任意识。

## 七、教学重点与难点

### 教学重点

- 从分析目的出发设计可视化，而不是从图形名称出发；
- 理解并应用ggplot2图形语法：数据、映射、几何对象和坐标系统；
- 依据图形证据回答“主要死亡原因是什么”。

### 教学难点

- 解释从柱形图到玫瑰图的坐标变换逻辑；
- 理解极坐标图中半径与面积的关系，避免用面积夸大差异；
- 在“视觉冲击力”和“准确比较”之间进行有依据的可视化决策。

### 难点突破策略

先绘制笛卡尔坐标系中的柱形图，再只添加`coord_polar()`观察图形变化，使学生看到“数据和几何对象没有改变，改变的是坐标系统”。随后用两个面积不同但半径接近的扇形，引导学生认识面积约与半径平方相关，并通过`scale_y_sqrt()`讨论面积编码的准确性。

## 十、关键学生互动设计

### 互动1：预测投票——制造认知冲突

**教师提问：**“战争中的士兵主要死于什么？如果没有数据，你的判断依据是什么？”

**预期表现：**多数学生可能选择战伤。教师保留投票结果，在证据图完成后再次投票，使学生感知“直觉—数据—结论”的变化。

### 互动2：变量—视觉通道卡片排序

每组获得四张变量卡和四张视觉通道卡，要求匹配并口头说明：

- 日期或月份→横轴位置/角度；
- 死亡率→柱高/半径或面积；
- 死因→填充色；
- 改革阶段→分面。

该互动把`aes()`从代码形式还原为分析逻辑，避免学生机械模仿。

### 互动3：代码解释关卡

每组图形运行成功后，不立即判定“完成”。教师随机指定一名成员解释：

1. 这一行代码使用了哪一个变量？
2. 变量被映射到哪个视觉通道？
3. 删除这一层，图形会发生什么变化？

能够解释才算通过，防止组内“一个人写、其他人旁观”以及AI代写。

### 互动4：错误图会诊

提供故意错误的图和代码，例如：

- 把`fill="Cause"`写成属性设定，导致只有一种颜色；
- 用死亡人数直接比较不同时期，却忽略军队规模变化；
- 极坐标图未做面积校正，视觉差异被放大；
- 标题写成“卫生改革证明疾病已被消灭”，结论超过证据范围。

学生不仅修代码，还要说明错误如何影响判断。

### 互动5：图形选择辩论

一半小组主张向公众展示玫瑰图，另一半小组主张向分析人员展示柱形图或折线图。双方从受众、任务、准确比较和传播效果四方面陈述理由。教师总结：没有脱离分析目的和受众的“最好图形”。

3. 哪一种图形最适合向决策者说明问题？

### （三）数据字典

| 变量 | 类型 | 含义 | 使用提醒 |
|---|---|---|---|

#### 任务4：从柱形图变换为玫瑰图

为保证较小的扇形不被完全遮挡，先按数值从大到小安排绘制顺序。

```r
night_plot <- night[order(night$Rate, decreasing = TRUE), ]

p2 <- ggplot(
  night_plot,
  aes(x = factor(MonthNo), y = Rate, fill = Cause)
) +
  geom_col(
    width = 1,
    position = "identity",
    colour = "white",
    linewidth = 0.2
  ) +
  scale_y_sqrt() +
  coord_polar(start = 3 * pi / 2) +
  facet_wrap(~ Stage) +
  scale_fill_manual(
    values = c(
      "可预防疾病" = "#6AAED6",
      "战伤" = "#D95F5F",
      "其他" = "#8C8C8C"
    )
  ) +
  labs(
    title = "克里米亚战争中士兵死亡原因",
    subtitle = "扇形面积表示年化死亡率",
    x = NULL,
    y = NULL,
    fill = "死亡原因"
  ) +
  theme_void(base_size = 13) +
  theme(legend.position = "bottom")

p2
```

**思考：**玫瑰图中的扇形面积与半径平方有关。如果直接让半径与死亡率成正比，面积会夸大数值差异；`scale_y_sqrt()`使半径与死亡率平方根对应，从而使扇形面积更接近与死亡率成正比。

## 十四、教学创新点

1. **从“教函数”转向“解决可视化问题”。** 以分析目的组织ggplot2知识，函数只在项目需要时出现。
2. **从“复刻名图”转向“证据与决策”。** 学生先回答问题，再重构玫瑰图，避免课堂沦为代码模仿。
3. **从“生成结果”转向“解释逻辑”。** 通过映射卡、运行前预测和随机代码解释形成底层逻辑检查。
4. **从“美观评价”转向“准确、有效、负责”。** 把面积编码、受众适配和结论边界纳入评价。
5. **从“禁止AI”转向“分阶段人机协同”。** 先独立完成分析逻辑，再使用AI调试与评审，并通过日志留痕和口头答辩验证真实学习。
6. **从“一刀切任务”转向“分层成果”。** A层保证基本成功，B层完成核心迁移，C层进入图形批判和伦理判断。

## 十五、课后迁移项目

建议用宁波真实数据完成一次同构迁移，使学生检验是否真正掌握“分析目的—图形选择—证据表达”的方法。

### 选题A：宁波空气质量变化

问题：不同季节的主要污染物是什么？治理前后或特定时间段是否存在变化？  
要求：先绘制便于准确比较的图形，再判断是否有必要使用极坐标图；提交图形选择理由。

### 选题B：宁波舟山港月度吞吐量

## 十六、教学风险与应对

| 可能问题 | 应对措施 |
|---|---|
| 背景讲述过长，挤压操作时间 | 背景控制在3分钟，详细材料课前阅读 |
| 学生卡在数据整理 | 提供清洗后的长数据，本讲只聚焦可视化语法 |
| 代码运行差异导致节奏失控 | 提供基础脚本和备用结果图，设置明确检查点 |
| 小组中只有一名学生操作 | 设置四类角色，随机抽取成员解释代码 |
| 学生只关注图形美观 | 评价表把问题匹配、数据正确和证据解释设为主要权重 |
| AI直接生成完整成果 | 先完成映射单，后开放AI；保留日志并随机口头答辩 |
| 玫瑰图被理解为任何情况下都更好 | 必须与柱形图比较，并讨论极坐标的感知局限 |

## 十七、板书与课堂主线建议

板书或主屏始终保留以下主线：

> 真实问题 → 分析目的 → 变量选择 → 视觉映射 → 图层构建 → 图表证据 → 可视化决策

图形语法可归纳为：

> 图形 = 数据（data）+ 映射（aes）+ 几何对象（geom）+ 标度（scale）+ 坐标（coord）+ 分面（facet）+ 主题（theme）

课堂结束时回到驱动问题，不以“我们学会了`coord_polar()`”收尾，而以“我们如何用一张准确、有效、负责任的图支持公共决策”收尾。
